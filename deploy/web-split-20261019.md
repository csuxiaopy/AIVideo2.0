# Web and analysis services

Public URLs remain http://172.16.166.229 and the legacy port-8100 URL.
Nginx serves the frontend and forwards API/WebSocket traffic to `web:8100`
through the host's published port 8100. The analysis service `app:8100` is
accessible only inside the Docker network.

`web` runs two Uvicorn workers with no GPU devices. It handles login, accounts,
reports, log queries, alert queries, display settings and evidence downloads.
Synchronous database work and image/report generation run in the thread pool.
It never imports the analysis pipeline or PyTorch and never starts capture.

`app` is the single analysis owner. Camera configuration and control, snapshots,
live previews, detector/model reloads, alert delivery and cleanup are delegated
to its existing handlers. This preserves runtime state and existing validation,
permissions and audit semantics. WebSocket messages relay from its event bus;
HTTP streaming preserves MJPEG and authentication cookies. Internal requests
carry a random `ANALYSIS_INTERNAL_TOKEN`, and the original session/CSRF checks
remain in place. The token is stored in the server `.env`, never in the image.
A PostgreSQL advisory lock rejects a second analysis owner before capture starts.

Web caches the remote runtime snapshot for one second. If analysis is unavailable,
Web keeps its database APIs available, marks runtime health unavailable, and returns
503 for delegated operations. Existing expensive SQL can still take seconds;
moving it off the event loop prevents it from blocking unrelated requests but
does not change the SQL execution time.

Use the split wrapper for future lifecycle operations:

```sh
sh deploy/split.sh ps
sh deploy/split.sh restart web
sh deploy/split.sh up -d --no-build
```

Do not use only the two older Compose files: the split overlay removes the
analysis port mapping and gives that mapping to Web. Keep analysis at one replica;
scale only Web workers/instances. The optional monitoring profile uses
`deploy/prometheus.split.yml` to collect actual analysis metrics through Web.
After container/frontend updates also run `sh deploy/nginx/publish-static.sh`.

Backup: `/data/yolo_vlm_monitor/.deploy-backup-20261019-web-split/`.
Previous image: `yolo-vlm-gpu:before-web-split-20261019`.
Split image: `yolo-vlm-gpu:web-split-20261019`, also tagged `production`.
Only the server's existing API sources plus the new boundary/entry modules were
deployed; unrelated changes in the development checkout were not included.

Rollback: stop/remove `web` with the split wrapper first; restore the original
server `.env` and backend files from the backup, retag the previous image as
`production`, then recreate `app` with the original two Compose files and
`--no-deps --no-build`. That returns port 8100 to the monolithic application.
Nginx and existing task-statistics database changes do not need to be reverted.
